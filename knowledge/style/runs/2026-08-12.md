- 한 문단에 한두 가지 사실이나 판단만 담고, 핵심 판단은 독립 문단으로 분리한다. (관찰 3/3건, confidence: medium)
- 문제 해결기에서는 상태 표현이나 흐름 블록으로 조사 단계의 전환을 보여주고, 분석문에서는 근거 문단 뒤에 짧은 해석 문단을 붙인다. (관찰 2/3건, confidence: medium)
- 회고에서 감정·행동·배운 점이 바뀌면 문단을 나누되 기술적 판단을 설명할 때는 필요한 만큼 문단 길이를 늘린다. (관찰 1/3건, confidence: low)

### 코드·목록·표

- 설정 오류를 다룬다면 잘못된 값과 수정된 값을 인접한 Markdown 코드 블록이나 인라인 코드로 구분하고, 바로 다음 문장에서 영향과 수정 이유를 설명한다. (관찰 1/3건, confidence: low)
- 요청 경로나 계층 관계가 원인 분석에 중요하다면 번호 목록이나 텍스트 흐름으로 시각화한다. (관찰 1/3건, confidence: low)
- 기여, 산출물, 참고 대상이 여러 개라면 결론과 분리된 짧은 Markdown 목록으로 정리할 수 있다. (관찰 1/3건, confidence: low)
- 표는 비교 축과 항목 간 대응이 분명할 때만 사용한다. 코드 블록의 언어 지정이나 표 정렬에 관한 반복 관찰은 없어 특정 문법을 강제하지 않는다. (표 관찰 1/3건, 코드 관찰 1/3건, confidence: low)

### 어조·전환

- 개인 경험과 기술 판단을 함께 다룬다면 1인칭을 유지할 수 있지만 사실, 가설, 반증 결과, 개인 의견을 구분한다. (관찰 2/3건, confidence: medium)
- 질문형 소제목을 사용했다면 바로 다음 문단에서 설명이나 근거로 답한다. (관찰 1/3건, confidence: low)
- 회고의 감정 표현은 실제 행동, 기술적 배움 또는 판단 변화로 이어질 때만 유지한다. (관찰 1/3건, confidence: low)
- 법적·윤리적 쟁점은 단정적으로 판결하지 말고 확인된 사실과 작성자의 해석을 나눈다. (관찰 1/3건, confidence: low)

### 결말

- 문제 해결기라면 수정 결과에 더해 다음 장애에서 재사용할 점검 원칙을 남긴다. (관찰 1/3건, confidence: low)
- 성장 회고라면 도입의 고민을 회수하고 달라진 관점과 다음 과제를 연결한다. (관찰 1/3건, confidence: low)
- 쟁점 분석문이라면 찬반을 과도하게 단정하지 말고 실무자가 확인할 조건으로 마무리한다. (관찰 1/3건, confidence: low)
- 참고 목록을 덧붙인다면 본문 결론과 분리하고 각 링크가 어떤 내용을 보충하는지 밝힌다. (관찰 1/3건, confidence: low)

### 편집 규칙

- Markdown 헤딩의 깊이를 일관되게 유지하고, 각 소제목의 첫 문단이 해당 질문이나 주장을 바로 이어받게 한다. (관찰 3/3건, confidence: medium)
- 코드·설정·출력값은 코드 블록 또는 인라인 코드로 일반 문단과 구분하되, 실제 초안에 없는 언어 표식이나 실행 결과를 추가하지 않는다. (관찰 1/3건, confidence: low)
- 링크는 관련 주장 가까이에 배치하고 설명적인 링크 문구를 사용하며, 링크만으로 논지를 대신하지 않는다. (관찰 2/3건, confidence: medium)
- 표는 단순 나열보다 행과 열의 대응이 유용할 때만 사용하고, 작은 화면에서 읽기 어려우면 목록으로 바꾼다. (관찰 1/3건, confidence: low)
- 태그, 팔로우, 프로필, 이전 글, 댓글 등 서비스 UI는 제거하되 작성자가 의도한 참고 링크와 목록은 보존한다. (관찰 3/3건, confidence: high)

### confidence

- Velog 입력은 3건뿐이며 회고, 디버깅, 기술 쟁점 분석이 각각 1건이다. 소제목 중심 구조와 짧은 문단은 반복됐지만 표본이 작아 종합 confidence는 medium이다.
- 제목, 도입, 결말, 코드 블록, 표의 세부 사용법은 대부분 단일 사례에서만 관찰되어 low confidence로 제한한다. 네이버 관찰이나 일반적인 Markdown 관행을 Velog 전용 규칙으로 전용하지 않는다.
