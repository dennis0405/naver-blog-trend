# Naver Style Playbook

## Human Rules

- 네이버 편집기에 바로 옮길 수 있는 읽기 흐름과 서식을 우선한다.
- 초안에 없는 사실, 수치, 날짜, 코드, URL은 추가하지 않는다.

## Current Observed Naver Style

### 제목

- 검색형 안내·해설 초안이라면 핵심 기술이나 대상을 앞에 두고 범위, 효용 또는 문서 유형을 뒤에 붙인다. (관찰 12/17건, confidence: high)
- 프로젝트·현장 회고라면 핵심 대상과 시행착오 또는 관점의 변화를 함께 예고한다. (관찰 5/17건, confidence: medium)
- 회차, 시점, 긴 부제는 연재 위치나 설명 범위를 실제로 구분할 때만 사용한다. (관찰 3/17건, confidence: low)

### 도입

- 안내·해설형 초안이라면 독자의 문제나 기술의 필요성을 먼저 제시하고 다룰 범위를 빠르게 밝힌다. (관찰 10/17건, confidence: high)
- 회고·리뷰형 초안이라면 시작 계기, 사용 맥락, 작성자의 역할 또는 초기 기대를 제시한다. (관찰 6/17건, confidence: medium)
- 학습 메모처럼 범위가 좁다면 긴 인사말을 붙이지 말고 기록 대상부터 시작한다. (관찰 1/17건, confidence: low)

### 구조

- 다룰 항목이 셋 이상이라면 설명형 소제목으로 나누고 각 절이 개념, 기능, 문제 또는 판단 하나를 담당하게 한다. (관찰 14/17건, confidence: high)
- 절차·실습형 초안이라면 준비·설정·구현·연동·검증의 선행 순서를 유지한다. (관찰 6/17건, confidence: medium)
- 회고·트러블슈팅 초안이라면 배경·문제·원인 탐색·해결·결과와 교훈 순으로 정리한다. (관찰 6/17건, confidence: medium)
- 연구 요약이나 비교처럼 장르 특유의 구조는 해당 목적일 때만 적용하고 네이버 전체 형식으로 강제하지 않는다. (관찰 4/17건, confidence: low)

### 문단 리듬

- 모바일 게시용 초안이라면 한 문단에 핵심 하나만 남기고 소제목과 문단 사이에 충분한 시각적 간격을 둔다. (관찰 14/17건, confidence: high)
- 핵심 용어·단계·판단은 독립된 줄로 분리할 수 있지만 문장을 임의의 길이로 잘라 파편화하지 않는다. (관찰 8/17건, confidence: medium)
- 코드 중심 실습에서는 짧은 설명과 예시를 교대하고, 회고에서는 짧은 감상 뒤에 기술적 원인이나 판단을 연결한다. (관찰 4/17건, confidence: medium)

### 코드·목록·표

- 선택지, 단계, 장단점 또는 반복 항목이 셋 이상이면 글머리표나 표로 정리하되 모바일 화면에서도 관계를 파악할 수 있는지 확인한다. (관찰 10/17건, confidence: high)
- 순서 준수가 필요한 절차에는 번호 목록을, 순서가 중요하지 않은 특징·진단 기준에는 글머리표를 사용한다. (관찰 5/17건, confidence: medium)
- 실습형 초안이라면 코드 앞에 목적과 주의점을 쓰고, 뒤에는 핵심 동작이나 결과를 설명한다. (관찰 4/17건, confidence: medium)
- 같은 기준으로 비교할 대상과 값이 충분할 때만 표를 사용하고, 표 아래에서 수치의 의미나 선택 조건을 해설한다. (관찰 3/17건, confidence: low)

### 어조·전환

- 안내·해설형 초안은 명확한 설명체를 기본으로 하고, 입문자를 위한 질문형 표현이나 대화형 존댓말은 제한적으로 사용한다. (관찰 10/17건, confidence: high)
- 회고·리뷰형 초안에서는 1인칭 경험과 감정을 허용하되 사실, 기술적 원인, 개인 평가를 구분한다. (관찰 7/17건, confidence: medium)
- 논점이 바뀔 때는 다음 단계, 시간 흐름, 비교 또는 요약을 알리는 소제목이나 짧은 전환 문장을 둔다. (관찰 10/17건, confidence: high)
- 영문 기술 용어와 약어는 첫 등장 때 역할을 설명하고 이후 표기를 통일한다. (관찰 14/17건, confidence: high)

### 결말

- 긴 안내·해설형 초안이라면 핵심 판단 기준을 압축하고 독자의 다음 행동을 한 가지로 좁힌다. (관찰 11/17건, confidence: high)
- 회고형 초안이라면 해결 결과와 재사용할 교훈을 정리하고 실제 후속 작업이 있을 때만 다음 단계를 예고한다. (관찰 6/17건, confidence: medium)
- 리뷰·비교형 초안이라면 장점과 제약을 함께 검토한 뒤 적합한 독자나 사용 조건을 제시한다. (관찰 3/17건, confidence: low)
- 신청, 문의, 링크 이동 같은 행동 유도는 정보 본문과 분리해 말미에 한 번만 둔다. (관찰 4/17건, confidence: medium)

### 편집 규칙

- 네이버 편집기에서 섞인 메뉴, 공감, 공유, 댓글, 방문 통계, 저작권 안내, 관련 글 문구를 본문에서 제거한다. (관찰 17/17건, confidence: high)
- Markdown 기호에 의존하지 말고 네이버 편집기에서 보이는 소제목, 일반 문단, 번호 목록, 글머리표, 표, 인용 요소로 변환한다. (직접 서식 관찰 7/17건, confidence: medium)
- 강제 줄바꿈, 보이지 않는 공백, 과도한 빈 줄을 의미 단위의 문단 간격으로 정규화하고 반복된 제목이나 설명은 한 번만 남긴다. (관찰 12/17건, confidence: high)
- 코드가 있다면 들여쓰기와 코드 경계를 보존하고, 코드 앞뒤의 설명을 일반 문단으로 분리한다. (관찰 4/17건, confidence: medium)
- 해시태그와 참고 링크는 본문 결론 뒤에 분리하고 주제와 직접 관련된 항목만 남긴다. (관찰 5/17건, confidence: medium)

### confidence

- 네이버 입력은 17건이다. 소제목 분할, 짧은 문단, 핵심 대상이 드러나는 제목, 용어 표기 통일, 인터페이스 제거는 여러 날짜와 장르에서 반복되어 종합 confidence가 high다.
- 코드, 표, 회고 어조, 연재 표식은 글의 유형에 따라 달라 medium 이하로 적용한다. 최근 표본에서도 장르별 편차가 컸으므로 특정 서식을 네이버 전체의 고정 관습으로 단정하지 않는다.
